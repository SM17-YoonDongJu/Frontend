현재 브랜치의 커밋 내역과 변경 사항을 분석해서 PR 메시지를 작성하고, 프로젝트 루트에 md 파일로 저장해줘.

## 분석 순서

1. `git log dev..HEAD --oneline` 으로 이번 브랜치의 커밋 목록 확인
2. `git diff dev...HEAD --stat` 으로 변경된 파일 목록 확인
3. `git diff dev...HEAD` 로 실제 변경 내용 확인 (너무 길면 주요 파일 위주로)
4. 커밋 메시지, 변경된 파일, 코드 diff를 종합해서 PR 메시지 작성
5. 작성한 PR 메시지를 프로젝트 루트에 `pr-[이슈번호].md` 파일로 저장 (이슈 번호 모르면 `pr-draft.md`)
6. 저장 완료 후 파일 경로 알려주기

## PR 메시지 형식

아래 형식을 **반드시** 따라야 해. 섹션 이모지와 한국어 유지.

```
## 🔗 관련 이슈
Closes #[이슈 번호 - 모르면 XXX로 표시]

## ✅ 작업 내용

### [작업의 배경/동기 - 왜 이 작업이 필요했는지 먼저 설명]

기존 구조의 문제점이나 개선 배경을 서술한다.

<br/>

### 1. [첫 번째 주요 변경 사항]

변경 내용 설명. 필요하면 before/after 코드 예시 포함.

#### 세부 항목
- `컴포넌트명` → 역할 설명

<br/>

### 2. [두 번째 주요 변경 사항]
...

## 💬 고민했던 부분 (기술적 결정이 있었을 때만 포함)

### [결정 제목]

왜 그렇게 결정했는지 이유와 트레이드오프 설명.
```

## 작성 스타일 규칙

- **배경 먼저**: 변경 내용보다 왜 변경했는지를 먼저 설명
- **구어체 한국어**: "~더라구요", "~했습니다", "~인 상태였습니다" 같은 자연스러운 말투
- **Before/After**: 구조나 코드가 크게 바뀐 경우 이전/이후 비교 포함
- **기술 근거**: 설계 결정이 있으면 왜 그 방식을 선택했는지 설명
- **섹션 번호**: 여러 독립적인 작업은 `### 1.`, `### 2.` 로 구분
- **코드 예시**: 변경된 인터페이스나 사용법이 있으면 코드 블록으로 보여주기
- **불필요한 나열 금지**: 파일 경로 목록 나열보다 변경의 의도와 맥락 설명
