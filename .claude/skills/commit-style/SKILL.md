# 커밋 메시지 컨벤션

실제 커밋 24개 분석 + 팀 결정(2026-06-18)으로 확정. **직접 커밋하지 말 것 — 메시지만 추천**하고 사용자가 직접 커밋한다.

## 형식

```
<type> : <한글 명사형 요약>

* <변경 1 — 명사형>
* <변경 2 — 명사형>
```

- **콜론 양옆 공백**: `feat : ...` (✅) / `feat: ...` `feat:...` (❌)
- **type 전부 소문자**: `feat` `design` `refactor` (✅) / `Design` `Refactor` `[Design]` (❌)
- 제목 끝에 마침표 없음.

## type 어휘 (전부 소문자)

| type | 용도 |
|------|------|
| `feat` | 기능·화면·컴포넌트 추가/구현 |
| `fix` | 버그 수정 |
| `design` | 레이아웃·헤더·푸터·디자인 토큰 등 UI 셸 (동작 없는 시각 구현) |
| `refactor` | 동작 불변 구조 개선 |
| `docs` | 문서·스토리북 스토리 |
| `test` | 테스트 추가/수정 (Playwright·RTL) |
| `chore` | 라이브러리 설치·설정·빌드 |
| `style` | 포맷·세미콜론 등 비기능 |
| `settings` | 프로젝트/모노레포 초기 세팅·하네스 |

판단 모호하면 "이 커밋의 핵심 변화가 무엇인가"로. 시각 셸만이면 `design`, 동작 추가면 `feat`.

## 제목 (subject)

- **한글 명사형 종결**: "구현", "추가", "도입", "구성", "수정", "초기화" 등. ("구현했다"/"구현함" ❌, "구현" ✅)
- **스코프는 괄호로**: `feat : 손해사정 요청 퍼널 4단계(보험금 입력) 구현`
- 한 줄로 무엇을 했는지 명확히. 50자 내외 지향(한글이라 유동적).

## 어휘 (흔한 개발 용어로)

- **종결 동사**(명사형, 통용 개발 용어): 추가 · 구현 · 수정 · 제거 · 분리 · 통합 · 리팩터링 · 마이그레이션 · 적용 · 도입 · 정리 · 처리 · 연동 · 검증.
- **명사도 통용어로**: 훅 · 스키마 · 핸들러 · 컴포넌트 · 타입 · 모듈 · 유틸 · 엔드포인트.
- **지어낸/어색한 표현 금지** — 실제 커밋·개발 현장에서 안 쓰는 말 만들지 말 것. 예: "동반" ❌ → "같은 커밋에 포함" / "스토리 추가".
- **스토리북**: `* Storybook 스토리 추가` (✅) / "스토리 동반" ❌.

## 본문 (body)

- **불릿은 `*` 만 사용** (`-` ❌). 변경 2개 이상 → `*` 불릿 나열, 각 줄도 명사형 종결.
  ```
  * 입력 정보 요약 화면 추가
  * 필수 동의 검증 추가
  * 분석 신청 훅 및 MSW 핸들러 추가
  ```
- **단순/단일 변경 → 평문 1~2줄** 또는 본문 생략.
  ```
  feat : 퍼널 단계 진입 가드 추가

  직접 단계 진입 시 선행 단계 완료 여부 검증
  미완료 단계로 리다이렉트 처리
  ```
- "왜"가 제목/디프에서 안 보일 때만 본문에 사유 추가. 자명하면 생략.

## 커밋 단위 (원자성)

- **한 커밋 = 한 의미 단위.** 컴파일·검증 가능한 최소 단위로 쪼갠다.
- 데이터 레이어: fetch 함수 단독은 무의미 → 스키마 1커밋, (API+훅+목) 1커밋처럼 묶음.
- presentational 컴포넌트 + `.stories.tsx`는 소비처 없이도 1커밋 가능(스토리북 검증).
- "하나 구현 → 커밋 추천 → 다음" 흐름. 무관한 변경 섞지 않기.
- 공용 UI 컴포넌트는 `.stories.tsx`를 같은 커밋에 포함(스토리북 규칙).

## 추천-only 정책

- 작업 후 **커밋 메시지를 코드블록으로 추천만** 한다. `git commit` 직접 실행 금지.
- 변경 파일 목록 + 추천 메시지(제목+본문) 제시 → 사용자가 직접 커밋.

## 실제 이력 기준 예시 (정규형으로 교정)

```
feat : 손해사정 요청 퍼널 6단계(확인·제출) 구현

* 입력 정보 요약 화면 추가
* 필수 동의 검증 추가
* 분석 신청 제출 기능 추가
* 제출 성공·실패 처리 추가
* 분석 신청 훅 및 MSW 핸들러 추가
```
```
feat : report 쿼리키 factory·캐시 상수 도입
```
```
chore : zod, react-hook-form, @hookform/resolvers 라이브러리 추가
```
```
design : customer 고객 페이지 헤더 CustomerHeader 구현
```

## 관측된 드리프트 (이 규칙으로 수렴 대상)

기존 이력의 불일치 — 신규 커밋은 위 정규형만 사용:
- 콜론 공백 혼용(`feat:` vs `feat :`) → **`feat :`로 통일**
- type 대소문자 혼용(`Design`/`Refactor` vs `feat`) → **전부 소문자**
- 구버전 `[Design] ... (#14)` 대괄호+PR번호 squash 스타일 → 폐기
