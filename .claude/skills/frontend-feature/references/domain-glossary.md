## 1. 서비스 정의 / 해결 문제

보험금 지급 결과에 **의문·분쟁 가능성**이 있는 사용자 대상. 보험금 산정의 **정보 비대칭**을 AI 리포트로 완화하고, 필요 시 **손해사정사 연결**까지 지원.

사용자가 스스로 못 보는 것 = 서비스가 짚어주는 가치:

- 적용 가능한 **특약 누락**
- **후유장해** 인정 범위
- **과실비율** 차이 (교통사고)
- 유사 사례 대비 낮은 보상
- 소액 사건은 손해사정 비용 부담으로 상담 자체 포기

## 2. 역할 (actor)

| 역할        | 별칭/라우트         | 핵심 권한                                                                                   |
| ----------- | ------------------- | ------------------------------------------------------------------------------------------- |
| 일반 사용자 | 고객, `(customer)`  | 리포트 요청, 결과 열람, 검수 리포트 비교·사정사 매칭                                        |
| 손해사정사  | 파트너, `(partner)` | 채택 가능 목록 열람, 케이스 채택·검수·전자서명 등록. **등록번호·전문분야(speciality) 보유** |
| admin       | (백오피스)          | 자격 검증·승인                                                                              |

- 역할 전환: 권한 있을 때만 상단바 드롭다운에 노출. 고객 ↔ 파트너 영역 이동.
- AI 초안은 **사용자에게 직접 노출 안 됨** — 사정사만 열람. 사용자 API로 초안 원문 조회 차단.

## 3. 핵심 플로우 2개

### (A) 고객 리포트 생성

1. 리포트 생성 버튼
2. **보험 유형 선택**: 실손(MVP 범위) / 교통사고 / 후유장해(MVP 범위) / 화재·누수 / 기타
3. **문서 업로드**: 보험사명+상품명 입력 OR 약관 PDF 업로드 / 특약(업로드 or 직접입력) / 진단서·의료·사고자료 / 보험사 지급결과·부지급 안내문
4. **사고·청구 입력**: 사고발생일·사고유형·치료내용·청구금액·보험사 지급결과 + 자연어 질문 (예: "보험금이 적게 나온 것 같아요")
5. (시스템) 문서 분석 → entity 추출(보험사·상품·특약·진단명·지급결과) → 약관·판례·분쟁 검색
6. **AI 리포트 산출**: 사건요약 / 관련 약관요약 / 적용 가능 특약 / 주요 분쟁 포인트 / 유사 사례 / 참고 가능 보상범위 / 추가 확인 필요 자료 / 전문가 상담 필요 여부

### (B) 사정사 검수 → 발행

전체: **AI 초안 생성 → 사정사 채택 → 검수 후 등록 → 사용자가 등록 리포트 목록서 사정사 선택(매칭)**

- **경쟁 검수 모델**: 여러 사정사가 같은 AI 초안을 독립 채택·검수·등록. 채택해도 목록서 안 사라짐. 채택 시 사정사별 작업공간 격리 생성.
- 매칭 전까지 **수수료 없음**.
- **채택 가능 목록** 노출 정보: 사고유형·보험사·상품명·AI초안 생성시각·채택 사정사 수.
- **심층 분석 리포트**(채택 사정사용) 구성: 적용 가능 약관(조항 원문 인용) / 청구 항목 체크리스트(+필요서류+절차) / 핵심 쟁점 분석(부지급·감액 대응) / 장해지급금 계산(진단명→장해분류표 매핑).
- **검수·수정**: AI 초안 인라인 편집 + 의견 추가. 수정 전후 diff는 품질 개선 근거로 수집. 본인 작업공간에만 반영(타 사정사와 격리).
- **검수 리포트 등록**: 전자서명(등록번호·성명·서명일시)과 함께. **등록 후 수정 불가**(불변 저장). 사용자에 인앱 알림.
- **사용자 검수 리포트 목록**: 등록된 복수 리포트 비교(사정사 이름·경력·전문분야·요약) → 매칭 요청.

## 4. 리포트 상태 흐름

```
[고객 측] 분석중(analyzing) → 분석완료(analyzed) → 검수완료(reviewed)
[사정사 측] 채택가능 → 채택됨(adopted) → 검수중 → 등록됨(published)
```

- 폴링 대상(staleTime 0): 손해사정 요청 리스트, 사용자 손해사정 프로세스 확인 — 상태가 실시간 변함.
- 리포트 상세는 staleTime Infinity — 확정된 내용이라 안 바뀜.

## 5. 용어 사전 (UI 라벨 정합성)

| 용어               | 의미                                           | UI에서                                                       |
| ------------------ | ---------------------------------------------- | ------------------------------------------------------------ |
| 쟁점(issue)        | 보험사 부지급·감액 시 대응 포인트              | 검수화면 **인정/수정/제외 판정 토글**, 쟁점 추가/삭제+코멘트 |
| 특약(rider/annex)  | 추가 보장 항목. **누락 특약 발견이 핵심 가치** | 적용 가능 특약 목록                                          |
| 후유장해           | 장해분류표 매핑 대상                           | 장해지급금 추정                                              |
| 과실비율           | 교통사고 책임 비율                             | 교통사고 유형                                                |
| 면책               | 보험사 지급 거절 사유                          | 거절 사유 분석                                               |
| 보상범위(estimate) | 참고 가능한 예상 범위(최소~최대)               | 범위바, 사정사가 확정 최소/최대 입력                         |
| 채택               | 사정사가 AI 초안 케이스를 가져옴               | 채택 가능 목록 → 채택                                        |
| 매칭               | 사용자가 검수 리포트 중 사정사 선택            | 매칭 요청 CTA                                                |
| 검수 배지          | 사정사 검수 완료 표시                          | 검수자 이름 + 의견 인용 + 배지                               |
| 비식별(가명정보)   | 사정사에게 의뢰인 정보 비식별 노출             | **비식별 배지**                                              |
| 전자서명           | 등록번호·성명·서명일시                         | 종합 의견 카드 서명란                                        |

> 단정적 보상금액 확정·법률 자문·대리 뉘앙스의 카피는 fe-qa가 컨벤션 리뷰와 별개로 **컴플라이언스 플래그**로 보고한다.
